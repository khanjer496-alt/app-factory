# Prompt — Calibrate Product Vision

Do not use this on a brand-new repository with little real history.

Read `VISION_GOVERNANCE.md` and `skills/vision/SKILL.md`.

Then run the vendored `/vision` process against this repository.

Requirements:

- use real merged PRs/commits/files as evidence;
- do not invent principles;
- check for an existing `VISION.md` first;
- use delta mode if an approved vision already exists;
- draft testable acceptance/refusal criteria;
- create hard hypotheticals where both sides are genuinely defensible;
- keep the product owner as the decision-maker;
- preserve verdicts/reasoning and changelog next to the final vision.

After approval, update `AGENTS.md` references only if needed; do not weaken existing engineering/security/cost rules.
