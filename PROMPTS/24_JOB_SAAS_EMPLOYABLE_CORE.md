# Prompt 24 — Employable-Style Job SaaS Core

You are working on a standalone Job SaaS generated by the App Factory.

Read first:
- `JOB_SAAS.md`
- `EMPLOYABLE_PRODUCT_REFERENCE.md`
- `BROWSER_AUTOMATION_CONTRACT.md`
- `DATA_SOURCES.md`
- `AUTOPILOT.md`
- `PRODUCT_SPEC.md`
- `SECURITY.md`
- `AGENTS.md`

Preserve the simple consumer promise:

`upload one CV -> verify Career Brain -> set job targets -> agent finds -> scores -> tailors -> truth-checks -> applies -> keeps proof -> learns`

Build/maintain these product requirements:

1. Keep Greenhouse, Lever, Ashby, SmartRecruiters, and Workday first-class discovery targets.
2. Workday must use the browser-discovery provider seam unless an explicitly authorized official integration is available. Do not fabricate employer credentials.
3. Every strong match gets its own tailored resume from verified Career Brain facts.
4. Run a separate truth check before submission.
5. Browser submissions should upload a final private proof screenshot to the internal proof endpoint before returning success.
6. Never retry a possibly successful employer submission just because proof capture failed.
7. Show `View proof` in the application tracker when evidence exists and an explicit missing-proof state when it does not.
8. Keep first-time onboarding to three steps: upload CV, verify facts, set search preferences.
9. Start users in review mode. Autopilot is earned after trust and remains guardrailed.
10. Track interview/offer/rejection outcomes and optimize toward those outcomes rather than application volume.
11. Keep REST + MCP agent distribution intact.
12. Keep all core flows mobile optimized.

Run migrations, typecheck, tests, build, and security checks before declaring the change complete.


Global-first: support job seekers and job markets worldwide. Do not hard-code a country, city, language, currency, or work-authorization regime into the default UX.
